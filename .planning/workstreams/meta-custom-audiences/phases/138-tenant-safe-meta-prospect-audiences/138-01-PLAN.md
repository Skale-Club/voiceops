<objective>
Replace the one-audience-per-organization prototype with the durable schema required for tenant-safe multi-audience reconciliation.
</objective>

<threat_model>
- Cross-tenant configuration or membership access (HIGH): every table carries immutable `org_id`, RLS uses `get_current_org_id()`, and service-role callers must filter explicitly.
- PII leakage (HIGH): membership persists hashes/fingerprints only; no raw email, phone, or access token columns.
- Duplicate/concurrent runs (MEDIUM): database uniqueness and claim/lock fields prevent two successful owners for one audience/run.
</threat_model>
