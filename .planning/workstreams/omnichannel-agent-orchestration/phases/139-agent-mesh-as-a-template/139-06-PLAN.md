<objective>
Remove Cuts & Culture's hardcoded business identity from its own six live agent prompts,
replacing it with the `{{business_name}}` / `{{business_location}}` tokens
`src/lib/org-templates/prompt-template.ts` (139-02) knows how to render. This is what makes
a FUTURE capture of this org's mesh into a template produce prompts that actually vary by
target business — today, capturing it verbatim would just copy "Cuts & Culture Barbershop"
into every installed org.

Purpose: 139-CONTEXT.md, design point 2 — "A prompt today hardcodes ... What varies is the
business." This plan is the one-time content fix that makes that statement stop being true.
It is generic (a literal-substring replace, not a hand-typed new prompt) and it is proven
safe by a roundtrip check: rendering the new template with THIS org's own facts must
reproduce the original text, or the script refuses to write anything.

Output: `scripts/templatize-agent-prompts.ts`, following the exact safety shape of
`scripts/provision-canary-graph.ts` (structural preview with zero args, validated dry run
with `--org`, write only with `--org` + `--apply`, refuses any org whose slug doesn't match
what the script was told to expect).
</objective>

Core function:
```ts
export function templatizeAgentPrompt(prompt: string, facts: TenantFacts): { changed: boolean; result: string }
```
Implementation: build the exact `{{business_location}}` rendering for `facts`
(`businessName` + `, ` + `businessAddress` when present, else just `businessName`) and
replace its first literal occurrence in `prompt` with the token `{{business_location}}`.
THEN, separately, replace any remaining literal occurrences of bare `facts.businessName`
with `{{business_name}}`. If neither substring was found, `changed: false` and `result ===
prompt` unchanged.

`assertRoundtrips(original: string, templatized: string, facts: TenantFacts): void` — throws
with a descriptive message (including the agent slug, passed by the caller) if
`renderPromptTemplate(templatized, facts) !== original`. Call this before any write, for
every agent whose prompt changed.

`main()`:
1. No `--org`: read every agent for... there is no org yet without one — this script always
   requires an org (it operates on live content, not a structural preview like the canary
   script's zero-arg mode). Requiring `--org` unconditionally is fine and safer here.
2. Resolve the org row, check `slug === expectSlug` (`--expect-slug`) before printing
   anything or considering `--apply`.
3. Call `resolveTenantFacts(supabase, orgId)` for that org — this becomes the substring the
   script hunts for AND the substitution facts (same organization, both directions).
4. For every agent in that org with an active prompt version: run
   `templatizeAgentPrompt(activePrompt, facts)`. If `changed`, run
   `assertRoundtrips(activePrompt, result, facts)`. Print the diff. If `--apply`: insert a
   new `agent_prompt_versions` row (`version` = current max + 1, `system_prompt: result`),
   then update that agent's `active_prompt_version_id`.
5. Without `--apply`: write nothing, print what would change per agent, exit 0.

This script is intentionally generic (any org, any agent) even though its first real target
is Cuts & Culture — no tenant name is hardcoded in the script itself; the tenant identity
comes only from `--org` + `--expect-slug` on the command line, exactly like
`provision-canary-graph.ts`'s own `--org` + the graph's declared `organization.slug`.
