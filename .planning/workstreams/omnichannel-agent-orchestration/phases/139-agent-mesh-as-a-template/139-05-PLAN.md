<objective>
Implement the install half of the `agents` asset group: given a captured snapshot
(139-01's `SnapshotAgent[]` / `SnapshotAgentPartnerEdge[]` / `SnapshotAgentChannelDefault[]`),
create the agents, their prompt versions, direct tool grants, partner edges, delegated
workflow grants, and channel defaults in a fresh target org — idempotently, and without
ever activating specialist routing.

Purpose: this closes 139-CONTEXT.md's named historic bug directly —
`scripts/provision-canary-graph.ts` never creates `agent_prompt_versions`, so every agent it
provisions is inert (`resolveAgent()` refuses to load an agent with no active prompt
version) until someone fixes it by hand, which is exactly what happened for Cuts & Culture
(see `.planning/workstreams/omnichannel-agent-orchestration/phases/137-shared-specialist-mesh/137-VERIFICATION.md`,
"What is NOT proven"). This plan makes that failure structurally impossible: there is no
code path in `installAgents()` that creates an agent row without also creating and pointing
at a prompt version in the same pass.

Output: `installAgents()` in `src/lib/org-templates/install.ts`, wired into
`installSnapshotIntoOrg()`, with `buildChecklist()` extended for the new group.
</objective>

  <action>
Implement `installAgents(admin: Admin, orgId: string, snapshot: OrgTemplateSnapshot, createdBy: string | null, counts: InstallCounts): Promise<void>` in `install.ts`, following the
file's existing per-function style (plain `async function`, mutates the shared `counts`
object, `console.warn` + `continue` on a non-fatal per-row failure — never throws for a
single bad row).

1. `const facts = await resolveTenantFacts(admin, orgId)` — once, reused for every agent.
2. For each `SnapshotAgent`:
   a. Render `const renderedPrompt = renderPromptTemplate(a.system_prompt, facts)`.
   b. Upsert the `agents` row on `(organization_id, slug)` — set every captured field EXCEPT
      `active_prompt_version_id` (that FK target doesn't exist yet on first install; set it
      in step (d)). Set `agents.system_prompt` to `renderedPrompt` too (that column is
      NOT NULL and unused by the runtime, but must hold a valid value — see 139-01's
      context note on why the runtime never reads it).
   c. Look up the agent's current `active_prompt_version_id` (if the agent already existed
      from a prior install) and its pointed-to `system_prompt`. If it already equals
      `renderedPrompt`, do nothing further for this agent (idempotent no-op) and move to the
      next one.
   d. Otherwise: insert a new `agent_prompt_versions` row — `version` = (this agent's current
      max version, from a `select max(version)` scoped to `agent_id`, default 0) + 1,
      `system_prompt: renderedPrompt`, `created_by: createdBy` — then `UPDATE agents SET
      active_prompt_version_id = <new version id> WHERE id = <agent id>`. These two writes
      happen for every agent that does not already have an equivalent active version —
      THIS IS THE STEP scripts/provision-canary-graph.ts is missing; do not make it
      conditional on anything other than the content-equality check in (c).
   e. `counts.agents += 1`.
3. For each agent's `direct_tools` (tool_name[]): resolve the target org's `workflows` row
   by `tool_name` (select, not insert — installWorkflows, if selected, already ran earlier
   in `installSnapshotIntoOrg()`'s existing sequential order). Missing workflow -> warn +
   skip. Existing `agent_tools` row for `(agent_id, workflow_id)` -> skip (already granted).
   Otherwise insert `{organization_id, agent_id, workflow_id}` (tool_config_id stays null,
   satisfying the XOR constraint) and increment `counts.agent_direct_tool_grants`.

Wire into `installSnapshotIntoOrg()`:
```ts
if (want.has('agents') && snapshot.agents?.length) {
  await installAgents(admin, targetOrgId, snapshot, createdBy, counts)
}
```
Place this call AFTER the existing `workflows` block (order matters: direct/delegated grants
resolve against target-org workflows that must already exist).
